# PayCycle AI — 결과 저장 · 프로필 · 전면 다국어

분석하고 끝나는 서비스에서, 결과와 프로필이 저장되고 다음 방문에서 이어지는 서비스로 전환합니다. 현재 UI 디자인과 서비스 흐름은 유지합니다.

## 현재 상태 (점검 결과)

- 저장소: 백엔드 미연결. 모든 상태는 `paycycle-context`가 localStorage 한 덩어리(`paycycle-ai-state-v2`)로 저장. 분석 결과는 급여 기록에만 남고 세금·출국 결과는 저장되지 않음(화면에서만 계산).
- 결과 화면: PayCheck / TaxCheck / ExitCheck 모두 위저드 마지막 단계에서만 결과를 보여주고, 다시 열람할 경로가 없음.
- 언어: 자체 사전(`src/i18n/dict.ts`, ko/en/vi/zh). 다만 룰엔진·법령·질문카드·상태 라벨이 한국어 문자열을 직접 생성하고, 화면 곳곳(캘린더 36곳, 대시보드 31곳, 온보딩 29곳 등)에 한국어가 하드코딩되어 언어를 바꿔도 한국어가 남음.
- 프로필: 온보딩에서 한 번 입력하면 수정 화면 없음. 프로필 페이지 자체가 없음.
- 외부 API/환경변수: 추가로 필요한 것 없음. AI OCR·번역은 기존 Lovable AI 게이트웨이 사용, 실패 시 직접 입력으로 폴백.

## 이번 작업 범위

### 1. 결과 저장 레이어 (교체 가능한 구조)

- 저장 인터페이스 `ResultRepository`를 정의하고, 구현체는 우선 localStorage 버전으로 제공합니다. 나중에 DB 구현체로 갈아끼우기만 하면 되도록 화면은 인터페이스만 사용합니다.
- 결과 3종을 `userId`(로컬 단일 사용자 ID) 기준으로 저장: 급여 확인, 세금 확인, 출국 준비. 각 레코드에 생성일시, 상태, 요약, 근거, 다음 행동을 포함합니다.
- 분석 완료 시 자동 저장 + "✓ 저장 완료" 토스트.

### 2. 결과 기록 화면 + 최신 결과

- 새 화면 `/records`: 급여 / 세금 / 출국 결과 카드 목록(최신순). 카드 클릭 시 저장된 스냅샷 상세를 재분석 없이 열람.
- 대시보드 상단에 기능별 "최근 결과" 3블록(최근 확인일 + 핵심 한 줄 + 자세히 보기).

### 3. 세금 결과 화면 통합

- "확인해야 할 혜택"과 "최종 요약"을 하나의 **나의 세금 확인 결과**로 통합. 중복 섹션 제거.
- 한 줄 요약 + 상태 카드(🟢/🟡/⚪) 안에 현재 상태 · 판단 이유 · 필요한 자료 · 공식 근거를 간결히 배치.
- **다음 행동**은 별도 강조 카드(브랜드 강조색, 큰 글씨, 번호+아이콘)로 분리해 가장 눈에 띄게 표시.

### 4. 전면 i18n (i18next로 교체)

- `i18next` + `react-i18next` 도입, 네임스페이스 분리(common / home / onboarding / profile / paycheck / tax / exit / calendar / records / chat / legal). 기존 `useT`는 얇은 호환 래퍼로 유지 후 점진 제거.
- ko / en / vi / zh 4개 언어. 화면·모달·Drawer·툴팁·토스트·빈 상태·버튼·에러·날짜 문구까지 전부 키화. 하드코딩 한국어를 화면 컴포넌트에서 제거합니다.
- 결과 문장도 전부 번역: 룰엔진은 한국어 문장 대신 `{키, 파라미터}` 형태를 반환하고, UI에서 번역해 렌더링합니다. 상태 enum(EXPLANATION_REQUIRED 등)은 값 그대로 저장하고 표시할 때만 번역합니다.
- 법령은 조문 원문 키를 4개 언어로 번역하되, 법령명·조번호는 한국어 원문을 함께 표기합니다(관공서 제출 시 정확성).
- 언어 변경은 새로고침 없이 즉시 반영되고, 보고 있던 분석 결과는 유지됩니다(결과는 키+데이터로 저장되므로 언어와 무관).

### 5. 내 프로필 화면

- 새 화면 `/profile`, 헤더 프로필 아이콘과 탭에서 접근.
- 섹션: 기본 정보(표시 이름·국적·사용 언어) / 체류 정보(체류자격 ⓘ·입국일·예상 출국일) / 근로 정보(근로 상태·사업장명·근무 시작일·계약상 급여일) / 금융권리 요약(연말정산 확인 여부·출국 준비도·최근 급여 확인일).
- 섹션별 [수정] → 인라인 편집 → [저장]. 저장 즉시 전역 상태에 반영.
- 안내 문구: "입력하신 정보는 서비스 분석을 위해 사용됩니다 / 민감정보는 필요한 범위에서만 저장합니다". 계좌번호·외국인등록번호 등은 수집하지 않습니다.
- 프로필 변경 연동: 출국일 변경 → 캘린더·D-Day·출국 준비도 즉시 재계산. 체류자격·국적·근로상태 변경 → 저장된 결과에 "프로필이 변경되어 다시 확인이 필요합니다 [다시 분석]" 배너 표시(기존 결과는 삭제하지 않고 stale 표시).

### 6. 대시보드 재구성

나의 금융권리 → 최근 결과 3종 → 금융권리 캘린더 → AI 어시스턴트 → 프로필 요약(+프로필 수정). 모든 블록은 저장된 실제 데이터와 연결됩니다.

### 7. 데이터 연결

프로필 → 급여 기록 → 세금 → 출국 → 캘린더가 동일한 `userId`와 단일 상태 저장소를 공유합니다. 기능별 독립 mock 데이터는 두지 않고, 샘플 체험 모드만 한 번에 전체를 채웁니다.

## 기술 메모

- 신규: `src/lib/paycycle/results.ts`(타입), `src/lib/paycycle/repository.ts`(인터페이스 + local 구현), `src/routes/records.tsx`, `src/routes/profile.tsx`, `src/i18n/locales/{ko,en,vi,zh}/*.json`.
- 수정: `paycycle-context`(결과 저장/조회/stale 플래그), `rule-engine`(문자열 → 번역 키 반환), `law.ts`, `question-card.ts`, `chat-intent.ts`, 전 라우트/컴포넌트의 문자열 키화, `app-shell`(프로필 아이콘·탭 추가).
- 기존 localStorage 데이터는 마이그레이션으로 새 구조에 흡수합니다.
- 외부 API 키·환경변수 추가 없음.

## 구현 후 검증

Playwright로 5개 시나리오 직접 테스트: 급여 저장→기록 재열람 / 세금 저장→다음 행동 표시→재열람 / 출국 저장→캘린더 반영→출국일 수정 후 D-Day·결과 갱신 / ko→en→vi→zh 전 화면 텍스트 전환 / 프로필 수정 후 관련 상태 반영. 남은 하드코딩 한국어는 발견 즉시 수정 후 재테스트합니다.
