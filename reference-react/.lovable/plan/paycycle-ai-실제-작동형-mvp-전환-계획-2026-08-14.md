# PayCycle AI — 실제 작동형 MVP 전환 계획

기존 UI/브랜드 톤과 5탭 구조는 유지합니다. 화면을 늘리지 않고, 지금 목업으로 남아 있는 부분을 실제 데이터 흐름으로 바꿉니다. AI는 Lovable Cloud의 AI 게이트웨이로 실제 연결하고(별도 키 불필요), 데이터는 지금처럼 기기 로컬에 저장합니다.

## 1. 현재 상태 점검 결과

실제로 동작하는 것
- 온보딩 8단계 입력 → 프로필 저장 → 새로고침에도 유지 (`src/state/paycycle-context.tsx`)
- 급여 비교 계산 자체는 코드 Rule Engine에서 수행 (`analyzePay`, 1,000원 오차 허용)
- 급여 검증 결과가 타임라인에 자동 기록되고 누적 급여에 합산됨
- 챗봇은 저장된 상태를 실제로 읽어 답함 (인텐트 규칙 기반)

목업이거나 고정값인 것
- 문서 추출: 파일명·파일 크기로 금액을 만들어내는 가짜 OCR. 계약 2,100,000 / 명세 2,340,000 / 입금 2,220,000이 사실상 고정 (`mock-ocr.ts`)
- 추출값을 사용자가 확인·수정하는 단계 없음
- 분석 애니메이션 단계가 실제 처리 결과와 무관하게 순서대로 재생됨
- 업로드가 계약서 → 명세서 → 입금내역 순서로 잠겨 있음
- TaxCheck의 "외국인 특례" 카드는 모호한 이름이며 조건과 무관하게 항상 노출, 거주자/비거주자 판정도 단순 일수 계산
- ExitCheck 4개 항목은 사용자가 손으로 상태를 바꾸는 구조(조건 판정 없음), D-30/-20 로드맵이 법정기한처럼 보임
- 질문카드 번역이 6개 언어 하드코딩 템플릿(고정 문장)
- 타임라인은 리스트일 뿐 캘린더가 아님

없는 것
- 근로 상태(취업 전/근무 중/퇴사 후/사업장 변경) 분기
- 날짜 검증 (0004-02-02 같은 값이 그대로 저장 가능)
- 샘플 사례 체험 모드
- 서버 API, 실제 OCR/LLM 연결

## 2. 데이터 구조 (Checkpoint 2)

`src/lib/paycycle/types.ts`를 확장합니다.

- `UserProfile` — 닉네임, 국적, 체류자격, 서비스 언어(질문카드는 한국어 병기 자동)
- `EmploymentProfile` — 근로상태(`PRE_EMPLOYMENT` / `EMPLOYED` / `SEPARATED` / `CHANGING`), 입국일, 최초 근무일, 현 사업장 시작일, 계약 급여일, 예상 출국일, 사업장 목록. 각 날짜는 `{ value, unknown }` 형태로 "모름/미정" 표현
- `PayRecord` — 급여기간, 사업장, 확정 입금액, 문서 3종의 확정 필드값
- `PaycheckAnalysis` — 항목별 대조 행(항목/계약서/명세서/입금내역/결과), 발견 사항, 근거, 부족 자료
- `TaxProfile` / `TaxAnalysis` — 거주자 판정 입력값, 제도별 상태
- `ExitProfile` / `ExitClaim` — 조건 입력값, 권리별 확인/부족 정보
- `CalendarEvent`(기존 TimelineEvent 확장) — 날짜, 분류, 출처 기능(pay/tax/exit/profile), 금액, 확정/권장 구분
- `ChatMessage`, `EvidenceSource`(법령명 + URL)

PayRecord는 캘린더·누적급여·TaxCheck·챗봇이 모두 같은 소스로 참조합니다.

## 3. API / AI 구조 (Checkpoint 5)

서버 함수(TanStack `createServerFn`)로 3개만 만듭니다. LLM 키는 플랫폼이 제공하므로 사용자가 준비할 키는 없습니다.

- `extractDocument` — 업로드한 문서 이미지/PDF를 AI 게이트웨이 멀티모달 모델(`google/gemini-3-flash`)로 보내 구조화 JSON(기본급, 수당, 공제, 실지급액, 급여일, 급여기간) 추출. 실패·판독 불가 시 `null` 반환 → "확인 불가"
- `explainResult` — 코드가 만든 대조 결과만 입력으로 받아 설명 문장 + 사업주 질문카드(한국어 + 서비스 언어) 생성. 금액 계산·판정은 절대 LLM에 맡기지 않음
- `chatAnswer` — 저장된 상태 요약(JSON)만 컨텍스트로 넣고 답변 + 이동 링크 생성. 데이터에 없는 내용은 "확인 불가"로 답하도록 강제

개인정보 마스킹은 서버 함수에서 전송 전에 수행(여권번호·외국인등록번호·계좌번호 패턴 치환)하고, 마스킹 완료 여부를 분석 단계 UI에 실제 결과로 표시합니다. 오프라인/실패 시에는 수기 입력 경로로 자동 전환해 흐름이 끊기지 않게 합니다.

## 4. 기능별 변경

### 온보딩 (P0)
- 첫 질문을 근로 상태로 변경하고, 상태별로 이후 질문·대시보드 카드 구성을 분기
- 사업장에 보낼 언어 선택 단계 삭제 → 서비스 언어 설정 하나로 통합
- 날짜 입력을 달력 + 직접 입력 겸용 컴포넌트로 교체, 표기 YYYY.MM.DD
- 검증: 연도 범위, 미래 입국일 차단, 근무 시작일 < 입국일 차단, 과거 출국일 차단, "모름/미정" 허용
- 마지막에 입력값 확인 화면("이 정보가 맞나요?")

### 금융권리 캘린더 (P0)
- `/timeline`을 월간 캘린더로 교체(월 이동, 날짜별 점 표시, 날짜 클릭 시 하단 상세)
- 프로필 날짜(입국·근무시작·출국), 매월 계약 급여일, PayCheck/TaxCheck/ExitCheck가 만든 이벤트가 모두 자동 표시
- 하단 고정 버튼 [이번 달 급여 검증하기] → PayCheck 이동

### PayCheck (P0, 최우선)
- 3개 자료를 순서 없이 독립 업로드 + 각 자료에 "직접 입력" 대안. 자료가 없어도 분석 실행 가능
- [급여 비교 시작] → 실제 단계별 상태 변화 표시(문서 인식 → 마스킹 → 추출 → 사용자 확인 → 기간 연결 → 금액 대조 → 날짜 대조 → 차이 탐색 → 결과)
- 추출값 확인 단계: 항목별 값 표시 → [맞습니다] / [수정하기], 수정값이 이후 계산에 사용
- 결과는 표(항목 / 계약서 / 명세서 / 입금내역 / 결과) + 상단 대형 요약("설명이 필요한 차이 1건")
- 근거 섹션: 확인된 사실 → 공식 기준 → 판단 범위 → 다음 행동 → 근거 법령(근로기준법 제48조, 시행령 제27조의2, 링크)
- [사업주에게 물어보기] → AI 생성 질문카드, 한국어/서비스 언어 각각 복사

### TaxCheck (P1)
- 카드 3개만: 거주자/비거주자 확인, 19% 단일세율 vs 일반세율 비교, 주택마련저축 소득공제. "외국인 특례" 카드 제거
- 상태는 4종(적용 가능성 있음 / 조건 미충족 / 추가 자료 필요 / 현재 정보로 판단 불가)만 사용
- 입력을 바꾸면 결과가 즉시 달라지고, 해당 없는 카드는 숨김. 누적 급여는 PayRecord에서 계산

### ExitCheck (P1)
- 디자인 유지, 상태를 수동 선택이 아닌 조건 판정 결과로 산출(체류자격, 동일 사업장 근무기간, 출국일, 보험·연금 자료 보유 여부)
- 항목마다 상태 / 확인된 정보 / 부족한 정보 / 필요 서류 / 다음 행동
- D-30 등은 "권장 준비일"로 표기하고 공식 기한과 시각적으로 구분

### 챗봇 (P1)
- 저장 데이터 요약을 컨텍스트로 하는 AI 응답 + 관련 화면 이동 버튼
- 데이터가 없으면 추정하지 않고 필요한 자료를 요청

### 샘플 체험 모드 (P0)
- 첫 화면과 PayCheck에 [샘플 사례로 체험하기] — 필리핀 E-9, 계약 2,200,000 / 명세 2,380,000 / 입금 2,260,000, 급여일 25일 vs 입금 27일. 클릭 한 번으로 프로필·문서·캘린더까지 채워짐

## 5. 표현 규칙

"임금체불", "불법 공제", "지급됩니다", "받을 수 있습니다" 등 확정·법적 판단 표현은 전 화면에서 사용하지 않습니다. 데이터가 없으면 0원이나 정상이 아니라 "판단 불가 / 추가 자료 필요"로 표시합니다.

## 6. 구현 순서 (승인 후)

1. 데이터 구조 + 날짜 검증 유틸 + 근로 상태 분기 온보딩
2. 금융권리 캘린더 + 이벤트 기록 레이어
3. PayCheck 전체 흐름(독립 업로드 → 추출 → 확인 → 대조 → 결과표 → 근거)
4. AI 서버 함수 3종 연결(추출 / 설명·질문카드 / 챗봇) + 마스킹
5. TaxCheck Rule, ExitCheck 조건 판정, 세 기능 → 캘린더 연결
6. 샘플 체험 모드 + Playwright 전 구간 실사용 테스트
7. `IMPLEMENTATION_REQUIREMENTS.txt` 작성(외부 계정·키·설정이 필요한 항목만)

각 단계가 끝나면 결과를 보여 드리고 확인을 받은 뒤 다음 단계로 갑니다.

## 7. 이번 범위에서 구현하지 않는 것

- 계정 로그인·기기 간 동기화(로컬 저장 유지 결정)
- 전체 연말정산 계산(3개 제도만)
- 국세청·근로복지공단·국민연금공단 실시간 조회 (공개 API 미제공, 공식 안내 링크로 대체)
- 실제 금융기관 입금내역 자동 연동(스크래핑)
