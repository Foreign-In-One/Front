# PayCycle AI — 위저드 UX 전환 + 4개 언어 전면 번역

현재 스택(TanStack Start + Vite + React 19, 로컬 저장)과 기존 디자인 시스템은 그대로 두고, 화면 흐름을 "한 화면 = 한 가지 목적"의 단계형 위저드로 재구성합니다. Next.js는 이 환경에서 사용할 수 없으므로 도입하지 않습니다.

## 1. 현재 상태 점검 (확인된 사실)

- 라우트: `/`, `/onboarding`, `/dashboard`, `/paycheck`, `/calendar`, `/taxcheck`, `/exitcheck` (파일 기반 라우팅)
- 상태: `src/state/paycycle-context.tsx` 하나의 Context + localStorage(`paycycle-ai-state-v2`)
- 계산은 모두 코드 Rule Engine(`rule-engine.ts`), 법령 문구는 `law.ts`에 하드코딩(AI 생성 아님)
- AI는 `ai.functions.ts`의 서버 함수 3종(문서 추출/설명·질문카드/챗봇) — Lovable AI 게이트웨이, 별도 키 불필요
- 다국어는 미구현. `language` 값은 저장되지만 UI 번역에는 쓰이지 않고 질문카드 템플릿에만 사용됨
- 한 화면에 정보가 몰려 있음: `paycheck.tsx` 654줄, `onboarding.tsx` 466줄, `calendar.tsx` 327줄
- 비자 선택에 설명(ⓘ) 없음, 출국 이벤트가 다른 일정과 같은 스타일로 표시됨

## 2. 다국어 (전체 UI 번역)

- `src/i18n/` 신설: `ko / en / vi / zh` 4개 사전 + `useT()` 훅 + Context
- 언어는 프로필과 분리된 별도 저장 키. 첫 화면 포함 모든 화면 우측 상단에 고정 드롭다운
- 온보딩 마지막의 "사업장 전송 언어" 단계는 삭제. 질문카드는 항상 `한국어 + 현재 서비스 언어` 병기
- 법령 조문·기관명은 번역하지 않고 한국어 원문 유지(오역 방지), 설명 문장만 번역

## 3. 공통 위저드 구조

`src/components/wizard/` 신설 — 진행 표시줄, 한 단계 본문, 하단 고정 [이전]/[다음] 바, 시작 화면(제목+설명+시작 버튼), 결과 화면 레이아웃을 공유 컴포넌트로 만들고 세 기능이 동일하게 사용합니다.

상태 색상 규칙도 토큰으로 통일: 🔴 반드시 확인 / 🟠 추가 확인 / 🟢 확인 완료 / 🔵 안내.

## 4. 화면별 변경

### 첫 화면 · 온보딩
- 언어 드롭다운 상단 고정, [시작하기] / [샘플로 체험하기]
- 비자 선택 항목마다 ⓘ Popover(E-9, H-2, F-2, F-4, F-5, D-2 등 2~3줄 요약)
- 날짜: 선택 즉시 다음으로 진행 가능, 별도 확인 화면 없음. 검증(미래 입국일, 근무시작 < 입국일, 과거 출국일, 연도 범위, "모름") 실패 시 짧은 오류 문구만 표시하고 진행 차단

### PayCheck (`/paycheck`)
[급여 확인하기] → Step1 근로계약서 → Step2 임금명세서 → Step3 입금내역 → Step4 추출값 확인/수정 → Step5 분석 → Step6 결과.
- 각 단계는 [건너뛰기]와 [직접 입력] 제공. 자료가 부족하면 결과를 "자료 부족"으로 표시하고 추정하지 않음
- 결과 상단: 큰 상태 한 줄 + 차이 금액 하나만. 그 아래 명세서 실지급액 / 실제 입금액 / 차이 3줄
- [왜 이렇게 나왔나요?] → 확인된 사실 / 가능한 확인 항목 / 공식 기준(근로기준법 제48조 + 공식 링크) / 판단 범위 순서
- [문구 복사] → 사업주에게 보낼 문장 클립보드 복사, "복사되었습니다" 토스트

### TaxCheck (`/taxcheck`)
[내 세금 확인하기] → 기본 조건 → 추가 조건 → 세율 비교 → 확인할 혜택 → 최종 요약.
이미 입력된 국적·체류자격·근무시작일·누적 급여는 다시 묻지 않고 "확인된 정보"로 보여주기만 합니다. 결과는 항목 목록으로만 보여주고 클릭 시 상세로 이동합니다.

### ExitCheck (`/exitcheck`)
[출국 준비 시작] → 출국일 → 근무기간 → 보험/연금 → 필요 서류 → 준비 상태 → 최종 요약.
각 단계에 [수정] 버튼. 출국일을 바꾸면 캘린더 일정·D-Day·준비 항목·상태가 즉시 재계산됩니다.

### 캘린더 (`/calendar`)
출국 관련 이벤트는 전용 색상 + ✈️ 아이콘으로 분리(📄 서류, 💰 보험/연금, 🏦 지급 확인). 날짜 클릭 시 해당 날짜 준비 항목과 관련 화면 이동 버튼 표시.

### 챗봇
범용 챗 UI 대신 추천 질문 3개로 시작하는 금융권리 도우미. 답변 아래에 [급여 분석 보기] / [출국 준비 보기] / [세금 확인 보기] 이동 버튼을 붙입니다.

## 5. 서비스 레이어 · 외부 연동

- `src/services/` 신설: `ocr`, `ai`, `law` 각각 인터페이스 + `mock` 구현 + 실제 구현 자리. 실제 키가 없으면 자동으로 mock으로 동작하고 화면에 "샘플 판독" 배지를 표시
- OCR/AI는 Lovable AI 게이트웨이 사용(키 불필요), 법령은 하드코딩 데이터 + 공식 링크, DB는 도입하지 않고 로컬 저장 유지
- `EXTERNAL_SETUP.md` 작성 — 실제 외부 설정이 필요한 항목(국세청 API, 유료 OCR 대안, 법령정보 API, 계정 동기화용 DB)만 용도·문서 URL·인증 방식·환경변수명·현재 Mock 여부로 정리

## 6. 구현 순서

1. i18n 기반 + 언어 드롭다운 + 공통 위저드 컴포넌트
2. 온보딩(비자 ⓘ, 날짜 UX) 개편
3. PayCheck 6단계 위저드 + 결과/설명 박스/문구 복사
4. TaxCheck 5단계, ExitCheck 6단계 위저드 + 재계산
5. 캘린더 출국 구분 + 챗봇 개편
6. 서비스 레이어 정리 + `EXTERNAL_SETUP.md`
7. Playwright로 전 구간 실사용 테스트 후 미구현·목업 잔여 항목 직접 수정

## 7. 이번 범위 밖

- Next.js 도입(환경상 불가), 계정 로그인·기기 간 동기화, 전체 연말정산 계산, 국세청·공단 실시간 조회
